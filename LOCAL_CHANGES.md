# Local changes for Switch 2

Base: upstream **v3.3.7**, branch `switch2-local`.

These changes are local to this checkout and are not intended as an upstream PR as-is.
They were made while testing NUXBT with a Nintendo Switch 2 on a Raspberry Pi 5.

## Changes

1. **`nuxbt/cli.py`** — `macro` / `tui` / `remote-tui`:
   `-a/--address` was declared with `default=False`, so Click parsed it as a boolean
   flag and rejected MAC addresses. Changed to `default=None, type=str`.

2. **`nuxbt/controller/controller.py`** — set `DiscoverableTimeout` to `0`
   instead of `180` seconds. The Switch 2 pairing screen can take longer than
   three minutes, after which the adapter stopped advertising.

3. **`nuxbt/web/app.py`** — do not pass `reconnect_address` when creating a
   controller from the web UI. Switch 2 does not give the Pi a persistent link
   key (`Bonded: no`), so an automatic reconnect gets stuck in `reconnecting`.
   Always wait for a fresh pairing instead.

4. **`nuxbt/web/client/src/socket.ts`** and the built
   `nuxbt/web/static/dist/assets/index-*.js` — use Socket.IO **polling only**.
   The webapp runs on `uvicorn + a2wsgi`, which does not support WebSocket;
   the browser's upgrade attempt receives HTTP 403 and the UI keeps reconnecting.

5. **`nuxbt/web/templates/index.html`** — reference the JS bundle with
   `?v=polling` so browsers do not keep serving the old cached bundle.

## Built web assets

`nuxbt/web/static/dist/` and `nuxbt/web/templates/index.html` are generated by
`npm run build` and are ignored by upstream `.gitignore`. They are force-added
here because Node.js is not installed on the test Pi. If you rebuild the
frontend later, re-apply the polling-only change in `socket.ts` first.

## Switch 2 pairing note

The Switch 2 stores the controller's link key, but BlueZ on the Pi does not
(`Bonded: no`). Reusing the same adapter MAC after a disconnect therefore fails
with `Authentication Failure (0x05)` during the link-key exchange.

Workaround used by `switchctl.sh`:

- `enable` generates a new random Nintendo-OUI MAC on every boot;
- `newmac` rotates the MAC manually when a stale pairing is detected;
- the Switch then treats the adapter as a brand-new Pro Controller and pairs
  from scratch.

Tested on Raspberry Pi 5 (Debian 13, kernel 6.18) with a Switch 2; webapp reached
`connected` and accepted input.
